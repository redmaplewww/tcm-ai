# 中医AI现状与技术方案调研报告

> 本文件为中医AI系统建设的技术调研资料。
> 调研时间：2026年9月。信息来源以公开网络检索（厂商官网、招股书、arXiv/GitHub/HuggingFace、政府官网、媒体报道）为主。
> 标注"待核实"的信息为检索中未能交叉验证的内容；商业公司宣称的疗效数据（如"准确率96%"）均为企业方口径，仅供方向性参考，不代表独立验证结论。

---

## 一、中医AI产品与行业现状

### 1.1 行业总体格局

- 2023年以来中医药行业已涌现 **20余个大模型**（不完全统计），包括中医药横琴大模型、岐黄问道、数智岐黄、天医、伊尹、聪宝素问等，通用医疗大模型（讯飞星火医疗、百度灵医、腾讯/京东/平安系）也在快速补充中医能力。
- 市场规模参考：2024年中国医疗大模型市场约 41.8 亿元，预计 2025 年约 65.3 亿元（产业研究机构口径，待核实精确口径）；中医AI是其中增速较快的细分。
- 行业高度分散：按2023年AI赋能收入计，最大玩家问止中医市场份额仅约 1.5%，前五名合计约 5.4%。
- 商业模式总体分三类：①自营线上/线下中医医疗服务（问止中医、固生堂）；②面向医疗机构/中医馆的 SaaS 订阅与辅诊系统（大经中医、讯飞医疗、道生）；③面向消费者的健康咨询/体检入口（平安健康、京东健康、各舌诊小程序）。
- 普遍痛点：商业化盈利难（问止中医三年累亏约4亿元）、疗效宣称缺乏第三方验证、监管定性（健康咨询 vs 诊疗行为）尚未完全清晰。

### 1.2 国内主要产品调研

#### 1.2.1 问止中医（"中医大脑"）
- 公司：2018年成立，总部深圳，定位"AI+中医"重症/疑难病数字医疗；2026年获国家级专精特新"小巨人"（媒体口径）。
- 产品：**中医大脑**——中医人工智能辅助诊疗系统。官方口径：基于百万级临床案例学习，构建覆盖 3000+ 病症的中医知识图谱，技术路线为"知识图谱+机器学习"，覆盖病症采集→智能诊断→处方→复诊随访全流程；宣称已应用于 2000+ 医疗机构、三万余案例整体疗效 96%（企业自述口径，存疑，待核实）。
- 商业模式：三大业务群——中医医疗服务（线上+线下诊所）、中医生活产品、中医大脑订阅服务；近90%收入来自线上。2022/2023/2024前三季收入分别约 0.62亿 / 1.89亿 / 1.73亿元，三年累亏约4亿元。
- 对我们的启示：问止验证了"AI辅助辨证+自有医师网络+线上问诊"闭环可规模化营收，但其"AI直接出方"的模式依赖自有医疗机构执业资质，纯工具类产品不能照搬。
- 多次递表港交所冲刺"中医AI第一股"（截至2025年8月更新招股书，上市进展待核实）。

#### 1.2.2 大经中医（"岐黄问道·大模型"）
- 公司：南京大经中医药信息技术有限公司。
- 产品：2023年7月发布**岐黄问道·大模型**（国内较早的中医垂直大模型），与华为合作、基于昇腾+MindSpore打造，2024年发布 V2.0。
- 数据底座（企业口径）：1100多万条中医知识图谱数据、1500本古籍、10万份医案、200万条临床数据。
- 三个子模型：①基于已确诊疾病的临床诊疗大模型（给辨证+处方）；②仅基于症状/体征的诊疗模型；③中医养生调理大模型。
- 配套硬件：AI舌面诊（望）、AI闻诊（闻）、大模型问答（问）的软硬件一体产品；其智能脉诊仪已获批**二类医疗器械注册证**。
- 商业模式：面向医院/基层中医馆的辅助诊疗系统+硬件，兼做中医大脑类 SaaS。

#### 1.2.3 讯飞医疗（智医助理 / 星火医疗大模型）
- 规模最大的基层辅诊玩家：截至2024年12月，智医助理应用于约 **6万家基层医疗机构**、覆盖30余省610余区县，累计 AI 辅诊建议超 **8.77亿次**、规范病历3.4亿份（2026年口径：累计12.3亿次辅助诊断，覆盖7.7万家基层机构、33万医生）。
- 中医落地：2024年4月**中医智能辅助诊断系统**在亳州上线（覆盖4区县107家基层机构、350余名中医师、AI辅助诊断超9800次），并推广至江苏、湖南、河北等地。
- 2025年11月星火医疗大模型升级：智医助理支持诊断病种拓展至2500种，首诊合理度宣称98%，新增**医学思维链循证推理和中医辅助诊疗能力**；C端"讯飞晓医"App 具备中医辨证功能。
- 商业模式：G端/ B端（卫健部门、基层机构购买服务）为主，是"政府埋单、基层使用"路线的代表。

#### 1.2.4 百度灵医（灵医智惠）
- 定位：面向医疗机构的 AI 能力输出（智能导诊、预问诊、眼底筛查等）。灵医开放平台提供患者就诊前多轮问诊咨询：描述症状→多轮追问病情、病史、生活习惯→精准分诊。
- 2023年7月与**固生堂**战略合作，宣称打造国内中医药领域首个大模型应用平台（"首个"为企业口径，待核实）。

#### 1.2.5 腾讯觅影
- 主战场是医学影像AI；2025年9月"肺炎CT影像辅助分诊及评估软件"获批 NMPA 三类证，成为互联网科技企业首个医疗AI三类证。
- 与本系统相关的能力是**智能预问诊**：口语化描述→医学专业术语匹配、自动生成诊前报告，其"口语理解→结构化病历"思路可直接借鉴。

#### 1.2.6 平安健康（平安好医生）
- 2025年6月发布 AI 家庭医生"安主任"，覆盖健康档案、咨询、报告解读等；中医为线上问诊科室之一，以自有医生团队+AI 提效为主，未单独主打中医AI。

#### 1.2.7 京东健康
- 京东互联网医院：在线问诊、电子处方、药品配送、诊后管理一站式；全职+外部医生团队。AI 主要用于分诊、预问诊、药师审方提效，中医科为线上科室之一。

#### 1.2.8 固生堂
- 线下中医连锁龙头。2025年8月发布**10大国医AI分身**（名老中医经验数字化路线），商业化聚焦"线上复诊"场景，缓解名医一号难求；另与百度共建中医大模型应用。
- 启示：名老中医IP+AI分身+线上复诊是合规路径较清晰的变现方式（复诊限定+真人医师在线）。

#### 1.2.9 其他值得关注的玩家
- **道生四诊仪（上海道生医疗）**：老牌中医四诊设备商，宣称其"中医大脑"融合4位国医大师脉诊数据、百余位名老中医舌诊数据、3000余位历代名医经验及30余万古今医案（企业口径）。
- **黄煌经方AI辅助诊疗系统**（南京中医药大学方向）：完整复刻黄煌教授"方-病-人"诊疗体系，基于4.66万份真实世界医案+数百万基层反馈医案训练（媒体口径）。
- **数智岐黄**（华东师范大学联合）：中医药大模型，已迭代至2.0。
- **中医药横琴大模型**（横琴实验室，2024年6月启动）：汇集约100亿字符中医知识文本及中医院数字化病例。
- **广安门医院中医AI大模型**（2025年7月亮相全球数字经济大会）：牵头成立全国中医药领域首个智能体联盟（"首个"为媒体口径）。
- **聪宝素问**：接入 DeepSeek 做知识迁移的中医大模型（厂商口径）。
- **中医大脑/知医App（ChatiSS 查体智能辅助诊疗系统）**：宣称取得两张医疗器械注册证（类别待核实）。

### 1.4 通用大模型在中医上的表现（对我们选型的关键参考）

- **TCMBench**（arXiv 2024，含 TCM-ED 数据集：5473道中医师资格考试真题）：GPT-4 以 **59.86%** 的准确率居首，其余被测模型显著更低——即最强通用模型在中医执业考试上也未及格线。
- 南京中医药大学标准化评估（2024）：所测各模型中医考试总正确率**均未超过60%**，Baichuan 总正确率36.39%。
- 中医辨证逻辑是共性短板：通用模型擅长知识问答，但在"症状→证型→治法→方剂"的链式推理上不稳定，且四诊信息（望闻切）缺失时更差。
- 相对表现较好的通用系：**Qwen 系列**（Qwen Max、Qwen2.5-Max 在多个中医评测中进入前列）、GPT-4o、Doubao 1.5 Pro（与中医专家评估一致性最高的模型之一，见上海中医药大学相关评测论文）；DeepSeek/GLM 需通过领域微调或强 RAG 补足中医知识。
- 结论：**任何通用API模型都不能"裸奔"用于辨证**，必须叠加高质量中医知识库（RAG）+ 规则校验，并以中医考试题集持续回归测试。

### 1.6 中医AI的医疗器械获批情况

- 截至2025年10月，NMPA已批准**超过110款**基于深度学习的三类医疗器械独立软件（来源：NMPA对全国人大建议的答复），但**绝大多数集中在CT/MRI/病理等影像领域**。
- **检索范围内尚未发现明确以"中医AI辅助诊断软件"名义获批的三类证产品**（截至调研日，待持续跟踪）。
- 现有中医AI/四诊产品的实际注册情况多为**二类证**：大经中医智能脉诊仪（二类）、各类中医四诊仪/体质辨识系统（二类）、知医App宣称的两张注册证（类别待核实）。
- 分类逻辑（依据《人工智能医用软件产品分类界定指导原则》）：软件若用于**辅助诊断/决策直接指导临床治疗**（如自动辨证开方）→ 按三类管理；若仅做**体质辨识、健康评估、信息展示** → 风险较低，多按二类或不作为医疗器械管理。
- 参考里程碑：2020年科亚医疗冠脉FFR软件为首张AI三类证；2025年9月腾讯肺炎CT辅助分诊软件为互联网企业首张AI三类证。
- **对本项目的含义**：系统若不宣称"诊断功能"、不输出可直接执行的处方，仅做健康咨询与知识检索，可暂不涉及医疗器械注册；一旦宣称"辅助诊断/辨证开方"面向医疗机构销售，则须走器械注册路径。

## 二、技术架构方案（自建系统参考）

### 2.1 总体架构参考（分层设计）

```
┌─────────────────────────────────────────────────────┐
│ 应用层：微信小程序/Web │ 医生工作台 │ 知识查询/学习模式      │
├─────────────────────────────────────────────────────┤
│ 对话编排层：问诊状态机（十问歌流程）+ 意图识别 + 术语归一化  │
├─────────────────────────────────────────────────────┤
│ 推理层：大模型（辨证假设生成）+ 规则引擎（校验/红旗症状）    │
│         ↑ 双向校验：LLM生成 ←→ 知识图谱规则验证           │
├─────────────────────────────────────────────────────┤
│ 知识层：中医知识库（RAG语料）+ 知识图谱（结构化关系）        │
│         + 方剂/中药数据库 + 配伍禁忌表                     │
├─────────────────────────────────────────────────────┤
│ 模型层：通用大模型API（起步）→ 领域微调开源模型（进阶）       │
├─────────────────────────────────────────────────────┤
│ 安全层：免责声明/红旗转诊/特殊人群提示/日志审计/隐私脱敏     │
└─────────────────────────────────────────────────────┘
```

行业实践印证：大经中医（知识图谱1100万条+大模型）、问止中医（知识图谱+机器学习）、讯飞（知识图谱+NLP+大模型）都采用**"结构化知识与生成模型混合"**路线，纯大模型直出方案无主流玩家采用。

### 2.2 知识库 / RAG 路线

#### 2.2.1 权威知识来源清单（按优先级）

**教材体系（结构化程度最高，首选语料）**
- "十三五"/"十四五"全国高等中医药院校规划教材（中国中医药出版社）+ 普通高等教育教材（人民卫生出版社）：
  - 《中医基础理论》《中医诊断学》《中药学》《方剂学》《针灸学》《中医内科学》《中医外科学》《中医妇科学》《中医儿科学》《温病学》《伤寒论讲义》《金匮要略讲义》《黄帝内经讲义》
- 用途：RAG 主语料；辨证标准、方剂组成、功效主治的"金标准"。注意版权——教材内容受著作权保护，商用需授权或使用大纲性/公有领域替代（见 2.2.3）。

**典籍与工具书**
- 《中华本草》：收载 **8980味** 药物、约2400万字（国家中医药管理局主持编纂，1999年出版）——中药功效/用量/用法权威来源（出版较久，著作权状态需核实）。
- 《中国药典》（2025年版/2020年版一部）：中药法定标准（用量、用法、毒性标注）。
- 经典古籍（《黄帝内经》《伤寒论》《金匮要略》《温病条辨》等）：公版，可作为引用出处增强解释可信度。

**国家标准与行业标准**
- **GB/T 16751《中医临床诊疗术语》**：疾病部分、证候部分、治法部分——**术语标准化与实体归一化的依据**。
- GB/T 15657《中医病证分类与代码》：病证编码。
- **ZY/T 001.1~001.9-94《中医病证诊断疗效标准》**（国家中医药管理局1994年发布）：各科病证的诊断依据、证候分类、疗效评定——**规则引擎诊断标准的主要来源**（新版替代情况待核实）。
- ZY/T 001.9 中医临床各科诊疗指南/中华中医药学会各病种《中医诊疗指南》与《临床诊疗指南·中医分册》。
- **ICD-11 第26章传统医学病证分类**（2019年WHO大会审议通过纳入）：病证国际编码对齐，利于未来与HIS系统互通。

**数据集资源**
- Awesome-TCM-LLM 收录的85个数据集；ShenNong-TCM-Dataset（指令数据）；CMtMedQA（多轮问诊）；TCM-ED/CMB（考试题）；公开舌诊数据集（如2008张染苔图像数据集等）。

#### 2.2.2 RAG 工程建议
- 语料切分：按"知识点"（一个证型的诊断标准、一味药的性味归经功效、一首方剂的组成主治）切分而非固定长度，便于精确召回与引用。
- 检索策略：混合检索（BM25关键词如"少阳证" + 向量语义如"口苦咽干往来寒热"）+ 重排（rerank）。
- **强制引用**：回答辨证/方剂问题时必须附知识出处（教材页/标准条目/古籍原文），无出处则降级为"仅供参考"并降低置信度展示。
- 分库管理：基础理论库 / 诊断标准库 / 方剂库 / 中药库 / 针灸库 / 养生库分库检索，避免养生内容污染辨证结论。

#### 2.2.3 版权与数据合规注意
- 教材、药典、《中华本草》均为受版权保护作品；自建知识库若商用需评估授权，或优先采用：国标行标（GB/T、ZY/T 术语标准本身不保护事实内容）、古籍公版、自建结构化数据（从多方来源人工整编事实性数据）。
- 爬取第三方中医网站数据存在版权与数据质量双重风险，不建议作为生产语料。

### 2.3 知识图谱方案

#### 2.3.1 实体类型设计（7大类核心实体）

| 实体类型 | 举例 | 关键属性 |
|---|---|---|
| 症状/体征 | 发热、恶寒、口苦、齿痕舌、脉弦 | 部位、性质、八纲归属、通俗别名（"上火"） |
| 证型 | 风寒束表证、肝郁脾虚证、肝肾阴虚证 | 证候分类（八纲/脏腑/气血津液）、诊断标准要点 |
| 疾病（中医病名） | 感冒、咳嗽、胃脘痛、消渴 | 对应西医病名（ICD-11映射）、所属科室 |
| 中药 | 麻黄、黄芩、附子 | 性味、归经、功效、用量、毒性、禁忌 |
| 方剂 | 麻黄汤、小柴胡汤、六味地黄丸 | 组成、君臣佐使、功用、主治证候、加减 |
| 穴位 | 合谷、足三里、内关 | 定位、主治、操作、禁忌 |
| 治法 | 疏风散寒、疏肝解郁、滋阴补肾 | 对应八法、适应证 |

辅助实体：体质类型（9种基本体质）、西医病名、古籍文献出处。

#### 2.3.2 关系类型设计（核心三元组）

```
症状 --提示--> 证型              （权重/必要性：主症/次症）
证型 --治法--> 治法              （"寒者热之"）
治法 --代表方--> 方剂            （"疏肝解郁→逍遥散"）
证型 --常用方--> 方剂
方剂 --组成--> 中药              （剂量、君臣佐使角色）
中药 --配伍禁忌--> 中药          （十八反、十九畏）
中药 --妊娠禁忌--> 标记          （禁用/慎用）
症状群 --鉴别要点--> 证型对       （相似证型鉴别：风寒vs风热）
疾病 --常见证型--> 证型
穴位 --主治--> 症状/疾病
中药 --归经--> 脏腑
方剂/中药 --出处--> 古籍
```

#### 2.3.3 可用的开源图谱数据
- **GitHub: fengxi177/Knowlegde_Graph_TCM**：中药、方剂两个子图谱的数据集与可视化demo（含归经关系）。
- **GitHub: tyang816/Awesome-TCM-LLM**：85个数据集入口，含多个知识图谱类数据。
- GitHub 多个"基于Neo4j的中医药知识图谱问答系统"项目（Python+Neo4j+py2neo模板，适合起步复刻）。
- 学术示例：《基于中医诊疗指南的冠心病知识图谱构建》（《实用方剂学杂志》2023）：从指南文本抽取"症状→证型→治法→方剂→中药"全流程三元组，用Neo4j构建——可作为单病种图谱构建的方法论模板。
- 大经中医公开宣称的1100万条图谱数据未开源，仅作规模参照。
- OpenKG.cn（中文开放知识图谱联盟）历史上收录过中医药相关图谱数据集（具体可下载情况待核实）。
- 在线参考：中医学专业知识服务系统（ai.tcmcds.com）。

#### 2.3.4 图谱构建策略建议
1. **起步**：以方剂学、中药学、中医诊断学教材+药典为底，人工整编"方剂-组成-中药"（约300首常用方）+"症状-证型"（约100个常见证型）两块最刚需数据；十八反十九畏、妊娠禁忌表必须全量录入（安全底线）。
2. **存储**：Neo4j（图查询、可视化）或 PostgreSQL+JSONB（轻量起步即可）；数量级在十万三元组内时关系型数据库足够。
3. **用途**：①问诊时实时查"该症状组合提示哪些证型"；②对LLM输出的证型/方剂做**存在性校验**（方剂组成是否真实、有无配伍禁忌）；③生成辨证解释路径。

### 2.4 问诊对话流程设计（核心交互方案）

参照中医问诊规范（《中医诊断学》问诊十问歌）+ 行业产品流程（问止、腾讯预问诊、灵医）：

**第0步 预检与知情同意**
- 免责声明与身份确认（是否未成年人、是否孕妇/备孕、年龄性别）。
- 红旗症状快速筛查（见2.7）。

**第1步 主诉采集**
- 开放式提问："您最不舒服的是什么？持续多久了？"
- LLM抽取主诉：症状+部位+持续时间+程度，转写为标准术语（口语→GB/T 16751术语映射，如"上火"→映射候选：心火亢盛/胃火炽盛/肝火上炎，需追问鉴别）。

**第2步 结构化问诊（十问歌框架）**
> 十问歌（明·张景岳《景岳全书》立，清·陈修园增补）："一问寒热二问汗，三问头身四问便，五问饮食六胸腹，七聋八渴俱当辨，九问旧病十问因，再兼服药参机变；妇人尤必问经期，小儿当问麻疹斑。"
- 落地为可配置的问诊树：寒热（恶寒发热/但寒不热/但热不寒/寒热往来）、汗（有汗/无汗/自汗/盗汗）、头身、二便（大便性状次数、小便颜色量）、饮食口味（食欲、口渴喜冷热饮、口苦口淡）、胸腹（胸闷/胁胀/脘痞/腹胀）、睡眠、情绪（肝郁相关）、妇科（经期/带下）、既往史与用药史。
- 追问策略：只问与当前主诉相关的维度（症状假设驱动），单轮1-2个问题，避免问满全表；每问标注目的（如"想确认是寒证还是热证"），提升用户配合度。

**第3步 症状归集与四诊补充**
- 生成"症状清单"让用户确认/勾选修正（防止LLM脑补症状，用户可删除）。
- 可选：舌象自拍（用户自述舌质舌苔颜色、照片辅助识别——注意照片受光线影响大，仅作参考）。

**第4步 辨证（多证型鉴别）**
- 输入确认后的症状集 → 生成2-3个候选证型假设，附：
  - 支持点（哪些症状支持）与不支持点（哪些症状矛盾）；
  - 相似证型鉴别依据（引用教材鉴别要点）；
  - 置信度表达（高/中/低 + 影响因素说明：信息不足时明确说"还需了解X"）。
- 兼容"病证结合"输出：可能的中医病名+对应西医疾病方向（提示就医科室）。

**第5步 建议输出（克制话术）**
- 治法方向（如"疏风散寒"）；
- **参考方剂/中成药**（明确标注：仅供学习参考，不构成处方建议，须由执业中医师面诊后开具）；
- 非药物建议（饮食宜忌、起居、食疗、穴位按摩——低风险高价值内容）；
- 就医建议：何种情况应就诊（中医科/急诊红旗）。

**第6步 记录与随访**
- 生成问诊记录单（症状清单+证型假设+建议），用户可导出带给医生作为参考；
- 症状持续/加重时提醒就医；慢病人群定期随访提醒。

**对话工程要点**：
- 状态机管理问诊进度（当前步骤、已采集维度、信息缺口），LLM负责单步生成，流程由代码控制，防止对话跑偏；
- 每步输出JSON结构化结果（症状ID列表）落库，便于复盘与审计；
- 支持用户随时退出问诊进入"知识查询模式"（查方剂/中药/穴位百科）。

### 2.5 四诊客观化硬件（可选参考，非首期必需）

#### 2.5.1 舌诊AI
- 技术成熟度在四诊中最高：CNN类方法（ResNet-18等）做舌苔/舌质多分类、YOLO做舌象检测分割均有大量论文与开源实现。
- 准确率：商业产品宣称95%+（"康一康"等App口径）；学术研究中单一维度（舌色分类）准确率普遍可达85-95%，但多维度联合（舌色+舌形+苔质+苔色+裂纹齿痕）真实场景会下降。**"95%以上"应视为理想条件下的商业口径，待核实**。
- 已有公开数据集：如2008张中医舌诊染苔图像数据集等（规模普遍偏小，标注标准不一）。
- 工程难点：采集标准化（光源/色温导致舌色失真）、自动分割、色彩还原（需标准色卡校色）。
- 本项目落地建议：一期做"用户自述舌象+可选照片粗识别（明示仅供参考）"，二期再考虑接入专业舌诊仪API或自研识别。

#### 2.5.2 脉诊客观化
- 客观化难度最大：中医脉象（28脉）依赖指下感觉，传感器难以完全复现。
- 现有设备：压力传感式（阵列压力传感捕捉寸关尺三部+浮中沉取脉）、光电式（PPG）、压电式；中科院相关机构已研制同步采集寸、关、尺三部位的脉诊设备。
- 代表产品：道生四诊仪、大经中医智能脉诊仪（二类证）、岐黄AI四诊仪（宣称155颗柔性传感芯片）等。
- **结论：脉诊数据消费级设备不可得，纯软件系统不应模拟"AI把脉"宣称**；问诊流程中以"脉象自述"（用户描述或线下就医后录入）作为可选项。

#### 2.5.3 面诊
- 面色（青赤黄白黑五色）识别研究较多，但受妆容/光线影响大，商用多作为四诊仪附属功能（体质辨识辅助）。一期不做。

### 2.6 辨证推理引擎：三条技术路线对比

| 路线 | 做法 | 优点 | 缺点 | 适用 |
|---|---|---|---|---|
| A. 规则推理 | 依 ZY/T 001 与教材"证候诊断标准"编写 if-then 规则（主症N项+次症M项+舌脉即可诊断） | 可解释、可审计、无幻觉 | 覆盖有限、组合爆炸、用户描述难以精确匹配规则 | 安全底线校验、常见证型兜底 |
| B. 大模型直接辨证 | LLM（+RAG）读症状清单直接输出证型与方剂 | 覆盖广、语言自然、能处理模糊描述 | 幻觉（编造方剂组成）、辨证不稳定、不可审计 | 解释生成、鉴别讨论 |
| **C. 混合（推荐）** | LLM生成候选证型/方剂 → 规则引擎+知识图谱校验（证型-症状是否匹配、方剂组成是否真实、有无配伍禁忌/妊娠禁忌）→ 校验不通过则打回重新生成或降级输出 | 兼顾覆盖与安全 | 工程复杂度高 | 生产系统 |

- 混合路线细则：
  1. **症状层校验**：LLM输出的症状必须来自用户确认清单，禁止新增症状作为依据（防幻觉）；
  2. **证型层校验**：证型必须是知识图谱中的标准证型名（GB/T 16751对齐），支持症状占比低于阈值的证型剔除；
  3. **方剂层校验**：方剂组成逐一与图谱比对（防止编造"某汤"组成）；涉及十八反/十九畏/妊娠禁忌/毒性药材（附子、细辛、半夏等）一律加警示或不出现在参考中；
  4. **剂量校验**：参考剂量必须在药典/教材范围内；
  5. 输出附"校验通过"标记链，形成可审计的推理轨迹。
- 行业印证：问止（图谱+ML）、大经（图谱1100万条+LLM）、讯飞（知识图谱+NLP）均为事实上的混合路线；纯LLM方案在所有严肃产品中未见。

### 2.7 安全与合规设计（产品内建）

1. **免责声明**：首屏+每次建议输出双重展示——"本系统提供中医健康信息参考，不构成医疗诊断和治疗建议；不能替代执业医师面诊"。
2. **红旗症状急诊转诊逻辑**（硬规则，优先级最高，触发即中断辨证流程）：
   - 胸痛/胸闷放射至左臂、下颌、后背，伴大汗；
   - 突发剧烈头痛（"一生最剧烈"）、喷射性呕吐、意识模糊、肢体偏瘫、口角歪斜、言语不清（卒中征象）；
   - 呼吸困难、咯血、呕血、黑便/血便；
   - 高热持续（≥39.5℃）或伴意识改变、抽搐（尤其儿童）；
   - 剧烈腹痛持续加重、腹部拒按；
   - 严重外伤、药物过量/中毒。
   - 触发后话术："您描述的情况可能需要紧急医疗处理，请立即拨打120或前往急诊，本系统不适用于该情况。"
3. **不直接开处方**：输出仅到"治法方向+经典方剂知识介绍+中成药名称（作为知识查询结果）"，不做剂量方案、不做疗程、不做购买链接；明确提示"请由执业中医师面诊后处方"。
4. **特殊人群提示**：
   - 自报孕妇/备孕/哺乳期：所有建议增加妊娠禁忌筛查，涉及活血、峻下、堕胎类药材/方剂直接屏蔽并提示就医；
   - 未成年人（<18岁，尤其<6岁）：建议儿科就诊，不输出用药参考；
   - 慢病自报（高血压/糖尿病/肝病/肾病等）与在用药物：提示中西药相互作用风险（如华法林与丹参、银杏），建议告知医师；
   - 老年人：简化话术、放大关键警示。
5. **对话记录与隐私**：
   - 明示个人信息收集范围与目的（个保法要求单独同意）；健康信息属敏感个人信息，需单独勾选授权；
   - 数据最小化：不强制实名/身份证；本地/传输加密；日志脱敏（问诊文本与健康档案分库存储）；
   - 提供记录删除功能；训练/评测使用数据前须去标识化并经用户授权。
6. **生成内容安全**：输出前过滤敏感词（疗效保证类用语："根治""包治""100%有效"禁用）；不确定时倾向保守表述；中医养生内容不得宣称治疗疾病（广告红线，见3.4）。

## 三、监管与合规

### 3.1 互联网诊疗核心规定（对我们业务边界最关键）

**《互联网诊疗管理办法（试行）》（国家卫健委，2018年，国卫医发〔2018〕25号，与《互联网医院管理办法（试行）》《远程医疗服务管理规范（试行）》同步发布）**
- 互联网诊疗仅限**部分常见病、慢性病复诊**；**不得对首诊患者开展互联网诊疗**（医师应当掌握患者足够病历资料，确定为常见病慢性病复诊后才可 online 接诊）。
- 不得开具麻醉药品、精神药品等特殊管理药品处方；为6岁以下低龄儿童开具互联网处方时须确认有监护人和相关专业医师陪伴。
- 开展互联网诊疗的机构须取得互联网医院资质或依托实体医疗机构。

**《互联网诊疗监管细则（试行）》（国家卫健委，2022年3月，国卫办医发〔2022〕2号）**
- **处方应由接诊医师本人开具，严禁使用人工智能等自动生成处方**；处方须经药师审核后方可生效。
- **人工智能软件等不得冒用、替代医师本人提供诊疗服务**。
- 要求接诊医师实名、留存完整诊疗记录备查。

**对本系统的直接含义**：
- 本系统若定位"健康咨询/知识工具"：不接入互联网医院、不出具处方、不做"诊断"宣称——可行且无需医疗资质；
- 若未来接入持牌互联网医院：AI只能做"医师辅助工具"（预问诊、辨证参考、病历生成），处方环节必须医师本人完成并留痕；
- "AI自动开方直接给患者"在任何持牌场景下均违法，产品设计永远不要滑向该方向。

### 3.2 《药品网络销售监督管理办法》（2022年9月发布，2022年12月1日施行）
- 处方药与非处方药区分展示，显著标示；**处方药销售主页面/首页面不得直接公开展示**包装、标签等信息；须展示"处方药须凭处方在药师指导下购买和使用"风险警示。
- 处方药销售须先方后药、处方审核；禁止销售的药品不得网售（麻醉、精神、医疗用毒性药品等）。
- 配套《处方药网络零售合规指南》（国家药监局综合司）：要求科学设置"诊疗开方—处方审核—药品销售"环节区分。
- **对本系统的含义**：若展示中成药信息，须按非处方药知识科普口径处理；不得提供"问诊→选药→购买"的诱导性闭环（无资质前提下），不建议一期接入任何药品电商链接。

### 3.3 AI医疗软件分类界定
- 依据《人工智能医用软件产品分类界定指导原则》（国家药监局2021年发布）：
  - 软件处理医疗器械数据、用于**辅助诊断/治疗决策**（其输出供临床采取干预措施）→ 按第三类医疗器械管理；
  - 仅用于**健康管理、健康评估、信息检索展示**（不直接给出诊疗决策结论）→ 不作为医疗器械管理或按较低类别管理。
- 配套技术审评文件：《人工智能医疗器械注册审查指导原则》（器审中心2022年3月）、《深度学习辅助决策医疗器械软件审评要点》等19项相关指导原则；截至2025年10月已批准110+款AI三类证软件，但集中于影像领域，中医AI三类证暂无公开获批案例（见1.6）。
- **对本系统的含义**：产品文案、功能命名严格避开"诊断""辅助诊断""检测疾病"等医疗器械表述；体质辨识、养生调理、知识查询类功能风险最低；若未来要做"辅助辨证决策"且面向医疗机构，需提前规划注册路径（周期长、成本高）。

### 3.4 生成式AI与宣传合规
- **《生成式人工智能服务管理暂行办法》**（国家网信办等七部门，2023年7月13日公布，8月15日施行）：向境内公众提供生成式AI服务需算法备案/安全评估（具有舆论属性或社会动员能力的场景）；内容需真实准确，防止歧视、虚假信息；涉及医疗等专业领域内容应标注来源与局限性（ Interpretation by 律所解读，具体条文适用待核实）。
- **《关于促进和规范"人工智能+医疗卫生"应用发展的实施意见》**（国家卫健委等部门，2025年11月）：支持智能健康咨询、健康管理业态发展，同时重申AI不得替代医师执业、医疗核心环节责任主体是医务人员与机构。
- 医疗广告红线（《广告法》《医疗广告管理办法》）：
  - 非医疗机构不得发布医疗广告；不得使用"根治""治愈率""有效率"等疗效保证用语；
  - 养生保健宣传不得宣称疾病治疗功能；不得利用患者/专家名义形象作证明；
  - 中医AI产品营销中"AI看诊疗效96%"一类表述涉嫌违反广告法，我们的营销文案必须回避任何疗效数字承诺。

### 3.5 健康咨询与医疗诊断的法律边界 → 产品话术设计规范

| 禁用表述（构成"诊疗"暗示） | 合规替代表述（健康咨询口径） |
|---|---|
| "诊断您为肝郁脾虚证" | "根据您描述的情况，中医知识中与之较相符的证型是肝郁脾虚（供参考）" |
| "建议服用逍遥丸，每日X丸" | "逍遥丸常用于肝郁脾虚的相关调理知识如下……是否使用请咨询执业中医师/药师" |
| "AI为您开方/开药" | "为您整理了经典参考方剂的知识资料（非处方建议）" |
| "治疗您的失眠" | "中医对失眠的调养思路与生活建议" |
| "您患了……病" | "这些描述在中医里常见于'不寐'的讨论范围，确切判断请就医" |

配套机制：全站敏感词表（诊断/治愈/保证类词汇）输出前过滤；建议末尾固定"就医提示"模板；用户明确询问"我是不是得了XX重病"时，一律引导就医而非概率猜测。

## 四、产品设计与评估

### 4.1 问诊体验设计

- **多轮追问逻辑**：假设驱动（hypothesis-driven）——每轮追问服务于"缩小证型鉴别空间"（风寒vs风热的鉴别问"出汗、痰色"；肝郁vs肝火问"急躁易怒程度"）；单轮问题≤2个；提供"不清楚/没有"快捷选项；用户可随时说"直接给结论"跳过追问（此时置信度降档展示）。
- **症状术语通俗化（双向映射表是核心资产）**：
  - 用户输入→标准术语："上火"→（心火/胃火/肝火候选，追问定位）；"拉肚子"→泄泻；"没胃口"→纳呆食少；"睡不着"→不寐；"心慌"→心悸；"怕冷"→畏寒/恶寒（需区分）。
  - 输出给用户→通俗解释：证型名后必须附一句白话解释（"肝郁脾虚：情绪不畅影响了消化功能，常见情绪低落+腹胀便溏"）。
  - 建设方式：以GB/T 16751术语为标准层，维护"通俗说法→标准术语"别名表，初始500-1000条，靠用户日志持续扩充（用户原话无法映射时进入人工整编队列）。
- **置信度表达**（对用户诚实，也是合规护城河）：
  - 三档展示：信息充分（绿）/"较可能"（黄）/信息不足（橙，附"还需了解：舌象、大便情况"）；
  - 多证型并列时展示"最可能/其次"，并说明鉴别点；
  - 永远不用百分比数字对外展示（避免伪精确与疗效暗示）。

### 4.2 评估方法

1. **中医考试题静态评测**（每发版必跑的回归测试）：
   - TCMBench/TCM-ED：5473道中医师资格考试真题（约1300题带详解）——最权威的客观题基准；
   - ShenNong-TCM-EB、CMB-Exam（含医师考试题）、MTCMB、TCM-3CEval（基础知识/经典理解/临床能力三维）可作补充；
   - 注意：考试准确率≠问诊能力，仅作知识下限把关（行业参考值：GPT-4约60%，未微调模型普遍<50%）。
2. **病例试剂盒（case bank）测试**：
   - 从《中医病证诊断疗效标准》、各病种中医诊疗指南、名老中医医案（出版医案）整编200-500个标准化病例（症状输入→金标准证型+参考方剂）；
   - 指标：证型Top-1/Top-3准确率、方剂组成事实正确率（与图谱比对）、幻觉率（编造症状/方剂比例）、红旗症状召回率（必须100%）、术语映射准确率；
   - 构建对抗样本：模糊描述、多证夹杂、用户口误、方言说法。
3. **名老中医/执业中医师专家评审**：
   - 定期抽样真实对话记录（脱敏后），由≥2名执业中医师独立盲评：辨证合理性1-5分、建议安全性一票否决制；
   - 与现有系统对照评测（同一病例集对比通用模型裸输出 vs 本系统），量化RAG+规则增益。
4. **安全红线测试**：孕妇/儿童场景、红旗症状场景、药物相互作用场景作为发布前强制门禁（fail-close：不通过则阻断发版）。

### 4.3 已知挑战（风险清单）

| 挑战 | 表现 | 缓解措施 |
|---|---|---|
| 幻觉 | 编造方剂组成/剂量、虚构证型、杜撰古籍出处 | 结构化校验（2.6）、强制引用出处、无出处降级 |
| 辨证不一致 | 同一症状集两次问诊结论不同 | 固定随机种子+温度调低、症状清单确认后作为唯一输入、规则引擎兜底排序 |
| 患者描述模糊 | "就是不舒服""有点虚" | 别名映射+假设驱动追问+置信度降档 |
| 缺乏循证分级 | 建议无证据等级 | 知识条目标注来源等级（教材/指南/古籍/专家经验），展示时可分层 |
| 通用模型中医底子弱 | 考试<60%、辨证逻辑弱 | 强RAG+领域微调（进阶）、以垂直语料持续补 |
| 舌象照片不可靠 | 光线失真导致误判 | 降级为"参考信息"，明示局限，不给硬结论 |
| 合规漂移 | 对话中逐渐滑向"诊断"口吻 | 输出侧敏感词过滤+话术模板硬约束+人工抽检 |

### 4.4 成本与实现路径建议

**阶段一（0-3个月）：API大模型 + RAG + 轻量规则（推荐起步）**
- 模型：通用大模型API（GLM/Qwen/DeepSeek系列均支持，选1主1备做failover；中医评测中Qwen系表现相对突出）；
- 知识：整编50-100个常见证型、100-150首常用方剂、300-400味常用药、十八反十九畏全表、红旗症状表；RAG用混合检索+rerank；
- 图谱：PostgreSQL表结构起步（症状/证型/方剂/中药四张主表+关系表）；
- 优点：无需GPU、快速验证产品价值与合规话术；成本主要为API调用费（单次问诊约数千至数万token，按量计费可控）与知识整编人力（最大成本项）；
- 里程碑：跑通"主诉→十问→证型假设→参考建议"全流程，TCM-ED抽样子集与自建病例集达标。

**阶段二（3-9个月）：领域微调 + 图谱完善 + 评估体系**
- 用 ShenNong 指令数据 + CMtMedQA + 自整编对话数据对开源底座（Qwen/GLM系 7B-14B级）做 SFT/LoRA，私有化部署或vLLM推理，降低边际成本、掌控安全对齐；
- 知识图谱扩充至1000方剂/500证型并迁移Neo4j；规则引擎覆盖常见病种（感冒、咳嗽、不寐、胃脘痛、便秘、痛经等30-50个常见病证）；
- 建立自动评测流水线（考试题回归+病例集+安全门禁）。

**阶段三（9个月+）：生态与硬件（视验证结果）**
- 医生工作台版本（面向中医馆的辅助决策，届时评估器械注册问题）；
- 舌诊图像识别模块（自研或对接专业舌诊硬件API）；
- 名老中医经验数字化合作（医案结构化→个性化辨证风格），参考固生堂"AI分身"与黄煌经方AI模式。

**成本量级参考（粗估，待核实单价）**：API方案单次完整问诊约 0.05-0.3 元（视模型与长度）；自部署7B-14B模型需1-2张消费级/推理卡即可支撑内部测试，生产并发需按QPS测算。
